# Avito Bot Detection Challenge — Решение

Решение задачи по детекции ботов-парсеров на платформе Авито в рамках Data Science буткемпа.

Задача: по логу событий внутри 24-часового окна наблюдения предсказать, принадлежит ли сессия (`cookie_id`) автоматизированному сборщику данных (`target = 1`) или обычному пользователю (`target = 0`). 
Основная метрика — **Precision при Recall >= 0.70** (P@R>=0.7).

---

## 1. Важный нюанс в данных (устранение утечки)

При анализе `events.csv.gz` выяснилось, что в обучающей выборке присутствуют события за пределами суточного окна (`event_ts >= window_end_ts`). В частности, туда попали события вызова капчи (`captcha_shown`), которые почти в 100% случаев происходили у ботов. В тестовом наборе события ограничены строго границами окна.

Если использовать события «из будущего», модель ловит жесткий data leakage и переобучается на события, которых не будет в тесте. Поэтому перед извлечением любых признаков данные строго фильтруются по условию:
```python
window_start_ts <= event_ts < window_end_ts
```

---

## 2. Валидация (Time-Based Split)

Тестовая выборка по времени находится строго позже обучающей (с 20 по 26 апреля 2026). Случайный K-Fold сплит здесь некорректен: он заглядывает в будущее и дает завышенные, нереалистичные оценки.

Использована честная валидация по времени (Out-of-Time):
* **Train**: первые 10 дней трейна (с `2026-04-06` по `2026-04-15`, ~8.4k кук);
* **Val**: последние 4 дня трейна (с `2026-04-16` по `2026-04-19`, ~2.7k кук, 220 ботов).

Все эксперименты с фичами и весами моделей калибровались на этом отложенном окне.

---

## 3. Генерация признаков (Feature Engineering)

Всего собрана 171 фича. Признаки отбирались исходя из физики поведения автоматических скрейперов:

* **Поведение курсора (мышь)**:
  * Один из самых мощных сигналов. У живых пользователей на десктопе практически всегда есть движение курсора, разброс координат (`pointer_x`, `pointer_y`) и пройденная дистанция.
  * Боты на десктопе шлют события кликов либо вообще без движения мыши (`desktop_zero_pointer`), либо с фиксированными координатами.
* **Тайминги и паузы**:
  * Статистики межсобытийных интервалов (среднее, медиана, перцентили, IQR).
  * Коэффициент вариации интервалов (`std / mean`) и всплесковость — отлично отделяют скрипты с регулярным `sleep()` от естественного человеческого темпа.
  * Доли быстрых кликов (<0.5с, <1с) и длинных пауз (>60с, >300с).
* **Поведение в поиске и навигация**:
  * Глубина пагинации (`search_page_max`): обычные пользователи редко уходят дальше 3–5 страницы выдачи, в то время как боты методично сканируют страницы до 50–60+.
  * Число уникальных запросов и длина поисковой строки.
  * Паттерны переходов: непрерывный просмотр карточек подряд (`item -> item`), длинные серии без возврата в поиск (`max_item_streak`), отсутствие целевых действий (добавление в избранное, открытие контактов).
* **Суточная активность и распределение**:
  * Энтропия распределения событий по часам суток. Люди активны волнами и спят по ночам, боты работают равномерным потоком 24/7.
  * Доля ночной активности (01:00–06:00).
* **Каталог и география**:
  * Соотношение категорий и локаций: парсеры часто сканируют 1–2 целевые категории сразу по десяткам разных локаций.
* **User-Agent и платформы**:
  * Нестыковки между заявленной платформой и User-Agent (например, десктопная платформа при мобильном UA).
  * Маркеры скриптов и headless-браузеров (`headless`, `requests`, `urllib`, `scrapy` и др.).
* **Метаданные куки**:
  * Возраст куки к моменту начала окна наблюдения (новые куки против старых сессий).

## 4. Модели и результаты экспериментов

Обучались три семейства градиентного бустинга: **LightGBM**, **CatBoost** и **XGBoost**. Каждая модель дает высокий скор сама по себе, но они немного по-разному ранжируют пограничные случаи.

Финальный результат формируется взвешенным блендингом:
`0.45 * XGBoost + 0.35 * LightGBM + 0.20 * CatBoost`
с усреднением по 3 случайным сидам (`42`, `2026`, `777`). Это сглаживает предсказания вероятностей и устраняет резкие ступеньки в ранжировании.

### Результаты на валидационном сплите (Val >= 2026-04-16):

| Подход / Модель | Число фичей | P@R >= 0.70 | Recall @ 1% FPR |
|---|:---:|:---:|:---:|
| Baseline (RandomForest из quickstart) | 2 | 0.0926 | 0.1182 |
| LightGBM | 171 | 0.7230 | 0.5864 |
| CatBoost | 171 | 0.7440 | 0.5864 |
| XGBoost | 171 | 0.7673 | 0.5818 |
| **Ансамбль (XGBoost + LightGBM + CatBoost, 3 сида)** | 171 | **0.7750 – 0.7979** | **0.6091** |

## 6. Как запустить

### Окружение
Python 3.11+:
```bash
pip install -r requirements.txt
```

Для полного обучения ансамбля на 100% трейна и формирования `submission.csv`:
```bash
python train_predict.py
```

Также весь ход работы с визуализацией признаков и графиками метрик можно запустить в [solution.ipynb](solution.ipynb).
