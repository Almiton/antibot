# Решение кейса: Детекция ботов на Авито (Bot Detection Challenge)

## 1. Краткое описание подхода
Задача состоит в бинарной классификации пользователей (`cookie_id`) по логу событий внутри строгого суточного окна наблюдения:
* `target = 1` — автоматизированные сервисы парсинга и сбора данных (боты).
* `target = 0` — органический трафик пользователей (люди).
* **Метрика**: **Precision при Recall $\ge 70\%$ ($P@R \ge 0.70$)**.

### Ключевая концепция решения
1. **Предотвращение утечки данных (No Leakage)**:
   В обучающей выборке `events.csv.gz` содержались события за пределами суточного окна наблюдения (`event_ts >= window_end_ts`), в том числе события вызова капчи `captcha_shown`. В тестовом наборе таких событий нет. События были строго отфильтрованы по правилу `window_start_ts <= event_ts < window_end_ts`.
2. **Domain-driven Feature Engineering (171 признак)**:
   Вместо наивных агрегатов построена система признаков, отражающая специфику поведения скрейперов:
   * **Кинематика мыши**: движение курсора (`pointer_x`, `pointer_y`), скорость перемещения, пройденная дистанция, число уникальных координат и критический признак `desktop_zero_pointer` (клики в Web/Desktop без единого движения мыши).
   * **Временная динамика**: межсобытийные интервалы $\Delta t$ (среднее, медиана, квантили, IQR, min/max), коэффициент вариации $CV = \sigma/\mu$ (детектор `sleep`), параметр всплесковости $B = \frac{\sigma - \mu}{\sigma + \mu}$, доли пауз $< 0.5s, 1s, 2s, 5s$ и $> 60s, 300s$, сессионность.
   * **Суточная активность и энтропия**: энтропия распределения событий по 24 часам суток (боты работают равномерно 24/7), доля ночных событий (01:00–06:00), пиковая часовая концентрация.
   * **Поисковая навигация и семантика**: максимальная и средняя страница выдачи (`search_page_max` до 60+ у ботов), число уникальных поисковых запросов, средняя длина запроса, флаги глубокой пагинации.
   * **Спектр действий и переходы**: доли и объемы всех типов событий, соотношения (`photo_per_item`, `contacts_per_item`, `fav_per_item`, `item_per_search`), марковские переходы (`item->item`, `search->item`, `search->search`), максимальные длины непрерывных серий просмотров (`max_item_streak`, `max_search_streak`).
   * **Специфика каталога**: концентрация на 1-2 категориях при обходе десятков локаций (`loc_per_item`, `cat_per_item`, `items_per_cat`), доля профессиональных продавцов (`pro`).
   * **User-Agent и платформенная консистентность**: сигнатуры парсеров (`HeadlessChrome`, `Scrapy`, `curl`, `python-requests`, `urllib3`), детекция ОС и браузеров, проверка несоответствия платформы и User-Agent.
3. **Моделирование и ансамблирование**:
   * Обучены три семейства моделей градиентного бустинга: **LightGBM**, **CatBoost** и **XGBoost**.
   * Финальный скор формируется взвешенным мультисидным блендингом (`0.20 * CatBoost + 0.35 * LightGBM + 0.45 * XGBoost`, усреднение по 3 независимым сидам `[42, 2026, 777]`), что устраняет шум случайного разбиения деревьев и обеспечивает плавный ранкинг без ties.

---

## 2. Валидационная стратегия
Тестовая выборка по времени находится строго **позже** обучающей выборки (с 20 по 26 апреля 2026 года). Случайный K-Fold сплит приводит к заглядыванию в будущее и переобучению на временной тренд.

Использована честная **Out-Of-Time (Time-Based) валидация**:
* Обучение: первые 10 дней трейна (с `2026-04-06` до `2026-04-16`, 8400 кук).
* Валидация: последние 4 дня трейна (с `2026-04-16` до `2026-04-19`, 2691 кука, 220 ботов).
Дополнительно протестированы скользящие временные окна (rolling splits).

## 3. Результаты экспериментов

| Модель / Подход | Число признаков | P@R $\ge$ 0.70 | Recall @ 1% FPR |
|---|:---:|:---:|:---:|
| **Baseline (Quickstart RandomForest)** | 2 | 0.0926 | 0.1182 |
| **LightGBM** | 171 | **0.7230** | 0.5864 |
| **CatBoost** | 171 | **0.7440** | 0.5864 |
| **XGBoost** | 171 | **0.7673** | 0.5818 |
| **Ensemble (LightGBM + CatBoost + XGBoost)** | 171 | **0.7750 – 0.7979** | **0.6091** |

*Прирост метрики соревнования по сравнению с baseline составил более **+0.68** (увеличение точности почти в 8 раз при сохранении 70% полноты).*

## 4. Воспроизводимость и запуск

### Окружение
* Python: `>= 3.11` (протестировано на `Python 3.14.5`)
* Зависимости зафиксированы в `requirements.txt`:
```bash
pip install -r requirements.txt
```

### Структура файлов проекта
```
bot_detection_challenge/
├── data/
│   ├── train.csv           # Обучающая выборка
│   ├── test.csv            # Тестовая выборка
│   └── events.csv.gz       # Лог событий
├── metric.py               # Официальная метрика соревнования
├── solution.ipynb          # Полный воспроизводимый Jupyter Notebook с выводом графиков и результатов
├── train_predict.py        # Автономный скрипт обучения финального ансамбля и генерации сабмита
├── submission.csv          # Итоговый файл с предсказаниями для test.csv
├── requirements.txt        # Список зависимостей
└── README.md               # Описание решения
```

### Запуск генерации предсказаний:
```bash
python train_predict.py
```
Или выполните ячейки в `solution.ipynb`.
Скрипт формирует валидный `submission.csv` (ровно 4909 строк, колонки `cookie_id,score`, отсутствие NaN, значения в $[0, 1]$).
